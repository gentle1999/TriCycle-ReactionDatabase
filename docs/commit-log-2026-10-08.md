# 导入性能优化与 worker 恢复修复（2026-10-08）

本次提交汇总文件导入链路的已保留优化，包含解析进程调度、科学物化、数据库写入、队列一致性及中断恢复。没有保留 NumPy IPC 缓存或实验性二进制 COPY 方案。

## 最终实现

- 解析进程内的帧分块使用 worker 安全的单帧重建入口，避免 MolOP 原生批量入口在 spawned worker 中失败后把整块拆成逐帧 IPC。保留逐帧失败隔离，并记录真正发生的分块回退。
- 几何匹配按最多 256 个候选批量筛选距离不匹配项，再对存活候选执行完整精度、有限值、角度和二面角校验。预加载精确几何命中后必须读取的电荷、多重度、MOL 和原子属性，减少逐行查询。
- 显式氢校验与已验证 SMILES 序列化按不可变分子图证据使用有界缓存；分子图、原子顺序、电子态、原子映射、立体属性和序列化选项保持在对应缓存身份中。失败验证不缓存，不持有调用者的可变 MOL。
- 批量写入直接消费已有待写队列，避免重复构建身份索引。按实体类型缓存固定主键列名，复用已检查的 ORM 状态；每次仍读取当前主键值，保留失败文件截断、重复身份去重和 ORM 回退。
- 领取前对已完成且结果晚于队列请求的历史任务进行对账，保留解析物化结果并修正批次计数。正常补充只检查有界 FIFO 页，启动时分页扫描全部历史任务。同一 artifact 只发放一个有效租约，显式重解析与对账通过行锁保护。
- 新增迁移 `0062_staged_upload_claim_index`，并发创建 staged 队列的 `(created_at, id)` 部分索引，减少 FIFO 领取排序成本。
- 批量续租使用 `FOR UPDATE SKIP LOCKED`，避免持有部分行锁等待持久化事务而产生死锁。
- 流水线异常退出并取消、等待解析任务、数据库消费者和心跳后，下一轮重新回收孤立租约；遗留任务不再仅等待配置的一小时租约到期。正常循环仍只回收过期租约，强恢复沿用单 upload-worker 部署语义。
- upload-worker 启用 `PYTHONFAULTHANDLER=1`，记录后续原生故障的 Python 栈。此设置不表示原生崩溃根因已修复。

## 验证

最终代码的完整后端单元测试 858 项通过，耗时 303.28 秒；仅有既有 Starlette 弃用警告。之后加强了一小时未来租约的测试夹具，相关 worker/批次测试 16 项再次通过，覆盖解析、数据库写入与心跳同时运行时发生 ConnectionError/RuntimeError，并断言所有旧任务停止后才恢复领取。正常循环不会重复回收未到期租约。

此前队列修复通过 15 项数据库回归，包含真实双连接行锁竞争；批量写入及科学几何优化通过 16 项数据库回归，覆盖 COPY/ORM 回退、复合主键、重复对象、队列截断、主键变更及科学数据往返。提交前 18 个变更 Python 文件的 Ruff 检查和格式检查全部通过，git diff --check 通过。相关源码的 mypy/Pyright 在优化验证阶段通过。

单元测试入口隔离部署 `.env`，并使用可被 spawn 子进程重新导入的文件；读取生产认证配置造成的中间 401 结果未计入最终通过结果。

此前发现约 5.34 万个 staged 历史任务对应已完成 ingestion，重复领取会清除既有物化结果并使成功数下降。修复后的首次生产对账确认了 53145 项历史任务，恢复新文件净处理进度；不能将旧文件重复成功的毛字节数视为新文件吞吐。

## 撤回实验与剩余问题

MOL 文本暂存 COPY、普通内置类型二进制 COPY、Decimal 二进制帧 COPY 均未显示总流程平均收益，已撤回。NumPy 数组 IPC 候选在独立数据库受控三轮均值中约 +2.10%，但波动明显；上线观察出现退出码 139 的原生崩溃，已回滚并从本次提交撤回。

本轮 MOL 原生二进制探测错误地使用了与业务共用 PostgreSQL 实例的测试数据库，隔离不足，导致业务连接中断约 6.6 秒。数据库自动恢复，随后通过既有 worker 重启恢复流程回收 256 个遗留任务。该探测未进入应用源码；后续数据库实验改用独立容器。临时测试数据库、桶和 32 个对象、独立容器、生成密码文件及提取的核心转储副本已清理。

本次及旧版本原生崩溃转储的栈顶均映射到 libgcc 的同一相对地址，但转储被截断，不能确定根因，也不能仅凭栈顶相同排除候选改动影响。最终保留崩溃栈记录和中断恢复修复，不宣称此类原生故障已经解决。零异常结论仅覆盖上述最终观测窗口。
